- Each run now prints the deployed SHA and subject line.

## Decisions

- **Clone is client-side, not a `POST /todos/<id>/duplicate` endpoint.** The create endpoint already
  takes every field, and going through the form lets the user tweak the copy (usually the date)
  before saving. A server-side clone would have duplicated silently with no chance to edit.
- **Clone re-populates from the *saved* todo**, not the current form state — so "Duplicate" always
  means "a copy of this task as stored", which is predictable regardless of in-progress edits.
- **Deploy logic moved into the repo rather than the workflow YAML.** The workflow and `deploy.sh`
  had been parallel copies of the same steps and had already drifted apart. One source of truth now,
  versioned in git, and it runs under a real shebang with `set -euo pipefail` instead of relying on
  drone-ssh's shell semantics.
- **`git checkout main` + `merge --ff-only`, not `reset --hard`.** A hard reset would silently
  discard anything sitting on the server; ff-only fails loudly instead.

## Notable discoveries

- **Deploys had been silently no-opping since 2026-05-23.** `/var/www/markd` was left checked out on
  the `restructure/monorepo` branch after that work. `git pull --ff-only` therefore updated
  *that* branch's upstream, found itself already current, printed "Already up to date" and exited 0
  — so GitHub Actions reported green deploys while `main` never shipped. Four commits' worth of work
  had never reached production. Found by curling `/version` and getting `v56` when `v57` was expected.
- **`appleboy/ssh-action@v1` does not stop on error by default** — it returns the *last* command's
  status, so a failure mid-script is swallowed. `script_stop` is not a valid input on v1 either
  (it silently warns and does nothing). Use `set -e` inside the script.
- **The health check must poll, not use `curl --retry`.** The systemd unit sets
  `RuntimeDirectory=markd`, so systemd deletes `/run/markd` on stop and the socket briefly doesn't
  exist after a restart. That's `ENOENT`, which `--retry-connrefused` doesn't cover (it only handles
  `ECONNREFUSED`), so curl gave up instantly at 0 ms against a perfectly healthy app. Cost one red
  CI run to find.
- **The local checkout was 4 commits behind and nothing recorded it.** The May restructure was
  committed under a different git identity (`Derek Gillett <github@derekgillett.com>`) from another
  environment. First sign was a rejected push. Rebased cleanly — git followed the renames.
- **The May restructure was tested by checking the branch out on prod**, 1 minute after the first
  commit, with the hardening fix committed 19 minutes later. Sensible workflow; the only missed step
  was switching back to `main` afterwards. `deploy.sh` now refuses to deploy from a non-`main`
  branch, so that can't repeat silently.
